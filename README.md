# 🎮 Q*bert — Аркадная игра на Java

Реализация классической аркадной игры **Q*bert** на языке Java с использованием Swing и AWT.

Игрок управляет персонажем, который перемещается по вершинам изометрической пирамиды из кубических платформ. Основная цель — перекрасить все платформы, избегая столкновений с противниками и падения за пределы игрового поля.

## 🛠 Технологический стек

- **Java** — основной язык программирования.
- **Java Swing** — создание графического интерфейса и игрового окна.
- **Java AWT** — графическая отрисовка, обработка событий и работа с изображениями.
- **BufferedImage / Graphics2D** — работа со спрайтами и графическими элементами.
- **JUnit** — модульное тестирование игровых компонентов.

## ✨ Основные возможности

- Изометрическая игровая карта в форме пирамиды.
- Управление персонажем с помощью клавиатуры.
- Анимация прыжков между платформами.
- Изменение цвета платформ при посещении.
- Система игровых уровней с увеличением сложности.
- Противники с автоматическим случайным перемещением.
- Обработка столкновений и условий поражения.
- Сохранение текущего уровня между запусками игры.
- Звуковые эффекты и анимации переходов между экранами.
- Режим игры за персонажа и автоматическое прохождение с помощью бота.

## 🎯 Игровая механика

Игровое поле представляет собой пирамидальную структуру, состоящую из кубических платформ. Каждая платформа имеет собственное состояние, определяющее, была ли она перекрашена.

Основные игровые механики:

- **Перемещение:** персонаж прыгает между соседними платформами в четырёх направлениях.
- **Окрашивание:** при приземлении на платформу её состояние изменяется.
- **Победа:** уровень завершается после окрашивания всех платформ.
- **Противники:** монстры перемещаются по игровому полю и могут нанести урон персонажу.
- **Поражение:** происходит при столкновении с противником или выходе за границы пирамиды.
- **Уровни:** после прохождения уровня увеличивается сложность и количество противников.

## 🏗 Архитектура проекта

Приложение построено с использованием объектно-ориентированного подхода. Игровая логика разделена между отдельными классами, каждый из которых отвечает за определённую часть приложения.

Основные компоненты:

| Класс | Назначение |
|---|---|
| `Main` | Точка входа, создание и настройка игрового окна |
| `GamePanel` | Управление игровым циклом, состояниями игры и уровнями |
| `Player` | Логика управления персонажем, прыжки и столкновения |
| `Map` | Структура игрового поля, платформы и их состояния |
| `Entity` | Базовая логика игровых сущностей и анимации перемещения |
| `Monster` | Поведение противников и их перемещение |
| `KeyHandler` | Обработка клавиатурного ввода |
| `GameBot` | Автоматическое управление персонажем |
| `AnimationManager` | Анимации переходов и эффекты прозрачности |
| `SoundManager` | Управление звуковыми эффектами |

### Принцип организации игрового процесса

Основой приложения является игровой цикл, выполняющий обновление состояния объектов и перерисовку игрового поля с целевой частотой 60 FPS.

Основные этапы:

1. Обработка пользовательского ввода.
2. Обновление позиции персонажа и противников.
3. Расчёт промежуточных координат во время прыжков.
4. Проверка столкновений и игровых условий.
5. Обновление состояния платформ.
6. Отрисовка игрового поля и всех игровых объектов.

## ⚙️ Особенности реализации

- **Изометрическая проекция.** Разработана система преобразования координат игровой сетки в экранные координаты с учётом смещений и интервалов между кубами.
- **Анимация прыжков.** Перемещение персонажей реализовано с использованием линейной интерполяции координат и синусоидальной траектории для создания эффекта прыжка.
- **Управление состояниями игры.** Реализована система игровых состояний: стартовый экран, выбор режима, игровой процесс, переход между уровнями и экран поражения.
- **Игровой цикл.** Обновление логики и отрисовка выполняются в отдельном игровом потоке с контролем частоты кадров.
- **Система уровней.** При прохождении уровня создаётся новое игровое поле, а количество противников увеличивается.
- **Обработка столкновений.** Реализована проверка взаимодействия персонажа с противниками и границами игрового поля.
- **Сохранение прогресса.** Текущий уровень сохраняется в локальный файл `game_save.dat`.
- **Автоматическое прохождение.** Предусмотрен отдельный режим управления персонажем с помощью игрового бота.

## 🧪 Тестирование

Для проверки основных компонентов использовался JUnit.

Реализованы тесты для следующих классов:

- `PlayerTest` — проверка начального состояния персонажа, перемещения, прыжков и получения урона.
- `EntityTest` — проверка базовой логики игровых сущностей и математических функций перемещения.
- `MonsterTest` — проверка состояния противников, позиционирования и механики прыжков.

**Результат:** все реализованные модульные тесты прошли успешно.
